## 一、经历面试「连环追问 24 道母题」与反杀证据公式

> **底层逻辑（源自 [`ai-interviewer`](https://github.com/ouxxyy/ai-interviewer) `rules@0.3.0`）**：
> 真实业务主管面试从来不听你背 STAR 套话，而是专门针对你简历里的动词和数字做 **0–2 层深挖追问（Drill-down）**。只要答不出**「个人边界、基线分母、取舍代价」**三要素，前期包装得再华丽也会被一票否决。

### 1. 四大核心追问维度 × 24 道高频母题速查

| 追问维度 | 面试官原话母题（看到简历必问） | 候选人高频踩坑回答（红牌扣分） | 满分反杀证据骨架（五维高分公式） |
| :--- | :--- | :--- | :--- |
| **A. 个人贡献边界**<br>*(防“把团队功劳算自己头上”)* | 1. “这个项目一共几个人？去掉其他人的工作，**哪一个具体模块或决策是只有你做了才成立的**？”<br>2. “你写的是‘主导/负责’，当时的汇报线是什么？拍板权在谁手里？”<br>3. “如果把你从这个项目里抽走，换成另一个同级别同事，结果会有什么不同？”<br>4. “跨部门推进时最反对你的人是谁？你拿什么筹码或数据说服他的？”<br>5. “代码/方案里最难的那 20% 脏活是谁干的？能讲讲当时的报错或边界情况吗？”<br>6. “这个需求是老板直接命题的，还是你自己从数据里挖出来的？” | ❌ “我们团队一起讨论决定的，我主要负责整体协调和跟进……”<br>❌ “大家都做了很多，我参与了全流程。”<br>*(致命伤：主语永远是“我们”，面试官默认你是边缘打杂)* | ✅ **【三明治切割法】**：<br>“整个项目由 4 人协作（1 算法 + 2 后端 + 我）。其中**需求立项时的 300 条 Badcase 归因分类表、核心召回阈值从 0.72 调到 0.81 的 AB 实验方案、以及上线前的兜底降级规则**是我个人 100% 独立完成的；后端高并发改造由张工负责。” |
| **B. 指标口径与基线**<br>*(防“用大盘自然增长冒充个人业绩”)* | 7. “简历写‘转化率提升 35%’，**改版前的绝对值基线是多少？分母怎么定义的**？”<br>8. “同一时期有大促或买量增长吗？怎么剥离外部因素证明这 35% 是你改版带来的？”<br>9. “样本量（N）有多大？观察周期是几天？有没有看长尾留存还是只看了首日点击？”<br>10. “你提高了 A 指标，**作为代价，哪一个反向指标（Guardrail Metric）变差了**？”<br>11. “为什么选这个指标作为北极星，而不是直接看付费 ROI？”<br>12. “上线第一周数据如果不涨反跌，你的排查漏斗第一步看哪张表？” | ❌ “具体基线记不太清了，大概是从百分之几涨上来的，数据看板上是这么显示的。”<br>❌ “没有任何负面影响，所有指标都涨了。”<br>*(致命伤：工程与产品常识匮乏，疑似编造数字)* | ✅ **【分子分母 + 护栏指标法】**：<br>“基线是双周均值 4.2%（分母为进详情页 UV，日均样本 1.8 万），实验组跑满 14 天稳定在 5.67%（相对提升 35%）。采用同流分桶 AB 排除了大促干扰；**代价是页面平均停留时长缩短了 4 秒**，但核心下单转化未受损。” |
| **C. 方案取舍与架构权衡**<br>*(防“只会调包/照抄竞品，不懂 Trade-off”)* | 13. “当时除了你选的这个方案，**备选方案 B 和 C 是什么？为什么被你毙掉了**？”<br>14. “在这个场景下为什么非要用 Agent / RAG，直接写规则或调小模型不行吗？”<br>15. “你的方案单次调用成本（Token / 延迟）是多少？规模扩大 10 倍还能扛住吗？”<br>16. “如果只给你 3 天时间和一半研发资源，你会砍掉哪三个功能来保核心闭环？”<br>17. “当时参考了哪几家竞品？你故意没抄他们的哪个设计？为什么？”<br>18. “这套架构现在的硬伤是什么？再给你一次机会重写，你会改哪里？” | ❌ “因为当时看大家都在用这套框架/老板说这么做最好。”<br>❌ “用大模型效果肯定比传统规则好。”<br>*(致命伤：缺乏成本意识与第一性原理权衡)* | ✅ **【约束条件下的次优解公式】**：<br>“我们对比过纯正则规则（召回仅 52%）、微调 7B 模型（需标注 2 万条且排期 3 周）和工作流+Prompt 方案。受限于 **2 周上线死线与零标注预算**，我们先用‘确定性脚本预筛 + 轻量模型兜底’，把单次成本压在 0.008 元、P95 延迟 1.1s。” |
| **D. 踩坑复盘与抗压极限**<br>*(防“完美假履历，测真实实战经验”)* | 19. “这个项目里**你犯过最大的一个判断失误是什么**？当时怎么止损的？”<br>20. “有没有哪个功能上线后用户根本不用？你当时误判了用户的什么心理？”<br>21. “遇到业务方强塞不合理需求且下周就要上线，你最近一次是怎么顶回去的？”<br>22. “线上出过最严重的一次故障或 Badcase 客诉是什么？复盘后加了什么硬门禁？”<br>23. “你离开上家公司的核心卡点是什么？如果本岗位也有类似乱象你怎么处理？”<br>24. “如果入职第 1 个月没有任何现成文档和导师带，你前两周怎么交付第一个可见成果？” | ❌ “整个项目非常顺利，基本没遇到什么大坑。”<br>❌ “我最大的缺点就是太追求完美、加班太狠。”<br>*(致命伤：套路感过重，缺乏真实战场硝烟味)* | ✅ **【真坑 + 机制化防御公式】**：<br>“第一版我高估了用户手写长配置的意愿，上线 3 天完播率只有 11%。第 4 天我紧急把交互砍成‘3 个默认模板一键点选’，完播率回升到 48%，并在团队立了条规矩：所有新功能首屏输入项绝不超过 2 个。” |

## 二、招聘 JD 15 大高频黑话解码表与简历证据自检单

> **底层逻辑（源自 [`jd-resume-match`](https://github.com/ouxxyy/jd-resume-match) `jd-match-rubric/0.1.0`）**：
> 80% 的求职者海投石沉大海，是因为把简历写成了“岗位职责说明书（我负责了什么）”，而不是针对 JD 隐性痛点的“原文证据账本（我证明了什么）”。

| 序号 | JD 表面黑话 | HR / 用人经理不敢明说的真实现状 | 简历必须出现的「刚性证据锚点」（缺一即判定为 Gap） |
| :---: | :--- | :--- | :--- |
| **01** | “抗压能力强，适应快节奏创业氛围” | 需求朝令夕改、排期极紧、大概率常态化大小周或晚间响应 | 写出**极限短周期交付记录**（如“72 小时内完成从 0 到 1 原型验证并上线”）及多线并发排优方法 |
| **02** | “具备从 0 到 1 独立负责产品/模块经验” | 没有现成基建、没有老人带，招你来当即插即用的开荒牛 | 必须体现**冷启动期无资源破局**：怎么搭最小闭环、怎么找种子用户、第一批数据怎么跑通 |
| **03** | “结果导向，对核心业务指标/GMV 负责” | 老板只看短期可量化的转化/营收，务虚汇报活不过试用期 | 严禁只写“优化体验”；必须绑定**漏斗转化率、客单价、留存率或成本下降的绝对值与复算口径** |
| **04** | “优秀的跨部门沟通与推动落地能力” | 部门墙极厚，产研/业务/算法互不买账，需要人去撕资源 | 写清一次**打破跨团队利益冲突的实例**（统一了什么标准、用什么工具或数据推进了卡壳项目） |
| **05** | “熟悉大模型 Agent / RAG 落地，非调包侠” | 之前招过只会写 Prompt 的人，线上幻觉和延迟一塌糊涂 | 必须写出**评测集构建（Eval）、Badcase 分类率、确定性兜底脚本、成本/延迟压降数据** |
| **06** | “一专多能，具备全栈视野 / 产品技术复合背景” | HC 被砍，希望 1 个人干“产品+运营+前端/脚本”2 个人的活 | 在技能与项目里显式列出**AI 杠杆工具链**（如用 Claude Code / 自动化脚本独立完成原需 3 人配合的交付） |
| **07** | “负责存量核心业务的精细化运营与增长” | 红利期已过，自然流量见顶，需要抠细节从存量里榨出增量 | 突出**分群分层策略（Cohort）、A/B 实验迭代次数與胜率、流失召回漏斗拆分** |
| **08** | “对行业/竞品有深度洞察，规划演进路线” | 现有业务遇到瓶颈，老板也不知道下一步往哪走，要你写战报 | 准备一份针对该司产品的**结构化诊断或横评表**（直接作为简历附件链接，降维打击同批候选人） |
| **09** | “良好的代码规范/文档习惯，推进工程效能” | 祖传屎山代码、无单测、线上经常背锅，急需有人补自动化护栏 | 标明自己过往项目的**单元测试覆盖数、CI/CD 门禁拦截率、线上故障率下降比例** |
| **10** | “配合商业化团队完成客户交付 / 政企私有化” | 定制化需求极多，需要直接面对甲方驻场或改标书、救火 | 强调**标准化模块抽离能力**（如何把 80% 定制需求沉淀为配置化底座，把交付周期从月缩到周） |
| **11** | “协助负责人进行团队赋能与 SOP 沉淀” | 团队水平参差不齐或流动性大，需要把个人手艺变成流水线 | 列出你沉淀并被团队复用的**模板数、内部 Skill/脚手架、培训文档及带来的效率提升百分比** |
| **12** | “数据敏感度高，能独立完成归因分析” | 没有专职数分支持你，自己不会写 SQL/Python 就寸步难行 | 明确标出**独立取数建模能力**（SQL/Python/看板搭建）及通过异常数据波动抓出业务 Bug 的案例 |
| **13** | “有海外/出海产品增长或本地化实战经验” | 国内卷不动了想出海，但团队对海外合规与渠道两眼一抹黑 | 写明具体目标地区、海外增长渠道（SEO/GEO/Reddit/ProductHunt/KOL）及多语言合规实操 |
| **14** | “接受业务方向灵活调整，拥抱变化” | 组织架构频繁重组，可能入职三个月换一次老板或换一条赛道 | 展示**跨领域快速迁移方法论**（如何在 2 周内摸清一个陌生行业的北极星指标与核心供应链） |
| **15** | “薪资面议，提供极具竞争力的期权/绩效激励” | 底薪可能压在范围下沿，大饼画在年终奖或未上市期权里 | 面试展现高不可替代性以锁定 Base 下限；谈薪阶段务必使用下方【模块三】核实绩效兑现率 |

## 三、接 Offer 前必核实的「四态背调防踩坑 18 问」

> **底层逻辑（源自 [`sherlock-company`](https://github.com/ouxxyy/sherlock-company) 四态证据法则）**：
> 任何入职前信息都必须严格归入四种状态：**`[已证实 Verified]`**、**`[有线索 Signal]`**、**`[说法冲突 Conflict]`**、**`[还不知道 Unknown]`**。切记：**网上搜不到负面 ≠ 零风险（Unknown 绝不等于 Safe）**！

### 接 Offer 签字前必查 3 大红线 + 18 条核实清单

1. **【主体与合同红线（必达 Verified 才签字）】**
   - [ ] **01. 四个名字是否一致？**（招聘软件挂的品牌名 vs 面试办公地水牌名 vs 劳动合同公章主体 vs 五险一金缴纳主体，若不一致是否是外包或空壳子公司？）
   - [ ] **02. 参保人数与成立时间？**（天眼查/企查查核对合同主体的实缴资本与最新社保参保人数：若号称几百人团队但合同主体参保 <20 人，列为 `[说法冲突]` 重点追问。）
   - [ ] **03. 薪资结构写进合同哪一行？**（是全额写进劳动合同基本工资，还是拆成“底薪 60% + 绩效 40% + 补贴”？绩效考核标准谁定、历史平均系数是多少？）
   - [ ] **04. 试用期转正客观标准是什么？**（有没有书面的 30/60/90 天量化交付指标？过往半年该岗位试用期通过率是多少？）
   - [ ] **05. 五险一金缴纳基数与比例？**（是按实际全额工资足额缴纳，还是按最低基数缴纳？公积金比例是 12% 还是 5%？）
   - [ ] **06. 竞业限制协议与违约金条款？**（普通岗位是否被强制捆绑全行业竞业协议？补偿金标准是否合法明确？）
2. **【业务生死与岗位前任真相（面业务主管必问）】**
   - [ ] **07. 这个 HC 是新增还是替补？**（如果是替补，前任是因为晋升转岗、业务调整还是呆不住离职？这个坑空了多久了？）
   - [ ] **08. 部门未来的现金流与容错期有多长？**（如果是创新/AI 业务，集团给这个部门的预算周期是半年、一年还是按月审视？）
   - [ ] **09. 入职后前 90 天最核心的 1 个交付物是什么？**（如果主管支支吾吾说不出具体任务，说明需求极度混乱或只是招人备胎。）
   - [ ] **10. 直接汇报对象（+1）在公司呆了多久？**（空降不足 3 个月的新主管 vs 深耕 3 年的核心骨干，政治安全垫完全不同。）
   - [ ] **11. 产研配比与上下游支持完备度？**（招产品经理却没有配套研发，或招 AI 工程师却没有数据基建，入职即巧妇难为无米之炊。）
   - [ ] **12. 团队近半年的离职率与晋升通道？**（上一次团队内有人晋升或加薪是什么时候？）
3. **【现场环境与隐形文化排雷（实地/视频面试必看）】**
   - [ ] **13. 办公地点物理预警排查**：是否位于商住两用居民楼、偏远毛坯园区，或工位极其拥挤且贴满狼性冲刺/感恩标语？
   - [ ] **14. 作息与加班真实水位**：晚 20:30 后办公区亮灯率、周末是否强制日报/周报、IM 消息是否有“秒回考核”？
   - [ ] **15. 报销与工具审批链路**：正常的开发算力、API、办公软件或打车报销，是标准化流程还是需要层层刷脸审批？
   - [ ] **16. 公开與论交叉比对**：脉脉职言、小红书、V2EX、GitHub 离职吐槽与劳动仲裁公开文书中，是否存在高频重复的同一类控诉？
   - [ ] **17. 毁约/裁员历史记录**：过去一年是否有过应届生毁约、试用期第 5 个月卡点辞退或无赔偿变相劝退记录？
   - [ ] **18. 个人成长资产沉淀度**：在这家公司干满 1 年后，你的简历上能不能多出 2 条经得起【模块一】24 道追问考验的硬核战绩？

## 四、6 大主流互联网岗位「工作任务 AI 不可替代指数」基准表

> **底层逻辑（源自 [`mbai`](https://github.com/ouxxyy/mbai) 任务拆解模型）**：
